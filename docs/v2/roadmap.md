# RocketStocks v2 — Build Roadmap

> How the architecture in [architecture-brief.md](./architecture-brief.md) gets built. Strategy locked in [ADR-0028](./adr/0028-execution-strategy-greenfield-terminal-burn-in.md): **all-in greenfield, linear build, terminal burn-in gate, clean-slate cutover.** v1 is in code freeze and serves users untouched until cutover.

## Operating method

- **Spec-driven slices.** Every work item gets a half-page spec ([spec-template.md](./spec-template.md), instances in [specs/](./specs/)) *before* implementation: ADR links, interface, acceptance criteria, exact verification commands. Review happens at the spec and at the verification output, not line-by-line. Specs are updated in the same PR when reality disagrees; decisions that surface mid-build are promoted to new ADRs.
- **Appetites, not estimates** (Shape-Up style). Each phase has a fixed timebox; when it runs out, cut scope — never extend time. Slices that miss get re-specced smaller.
- **Replay-harness-first.** The deterministic replay engine (ADR-0023) is built with detector #1 and every detection slice thereafter ships with a golden fixture + semantic assertions. Warm-up and backtest reuse the same seam.
- **Contract-first for `serve` only.** The OpenAPI surface is authored and reviewed before endpoint implementation, driven by a Cowork-shaped consumer test. Internal bus events stay cheap to change until replay fixtures pin them.
- **Hard rules carried from the ADRs:** no ambient `datetime.now()` in domain code (injected `Clock`, enforced by lint/grep gate); validation at the edges (Pydantic); mutations fail loud; hypertable DDL lives inside Alembic revisions.

## Phase 2 — Data plane *(appetite: 6–8 weeks; re-spec at midpoint)*

**Opens with the detection-model design session** (just-in-time, ADR-0030): the novel options-flow detection model is designed against real payloads from the Phase-0 spike + Phase-1 skeleton, and closes as its own ADR/design note *before* detector slices start. v1's alert types are retired — nothing here is parity-checked against `docs/alerts/` (v1-historical). **Named session inputs:** (1) whether the model fuses **equity-bar context** from `BarClosed` (underlying price/volume — e.g., unusual flow against a flat price) with the options scan; if yes, the single alert class makes the streaming→detection seam load-bearing for real. (2) **Alert dedup/cooldown/escalation semantics** — re-fire suppression grain (per-contract vs. per-underlying), cooldown windows, and the **tiered threshold ladder** of the escalation lifecycle (ADR-0026 as amended: messages are never edited; a new alert posts when criteria crosses a further tier, referencing its parent — the alert taxonomy needs a parent-linkage seam, e.g. nullable `parent_alert_id` + tier in the config stamp); whether day-2 OI confirmation/denial participates (incl. downgrade posts) is a session decision. Warm-up loads per-subject last-tier state (ADR-0018), so the session must define what it is. (3) **The Phase-0 chain-spike findings** — what flow inference 5-min snapshot deltas empirically support. (4) **The scan-cycle reality** — the curated scan is a rolling ~4-minute call train, not an instantaneous snapshot; per-row `fetched_at`/`quote_time` are the event-time rule, never the cycle's nominal T.

- **Horizontals:** `UniverseManager` (two-band, priority/eviction — ADR-0019; **requires a full design note, not a half-page spec** — the note must cover the symbol master (Nasdaq Trader listing files — ADR-0025), instrument filter rules, diff-based listing/delisting/rename lifecycle, and the sizes glossary: ~500 streamed / ~5–6k optionable / ~10k listed) · warm-up from durable log (ADR-0018) · nightly 1-min EOD backfill + 5-min/daily rollups + compression policies (ADR-0021/0022) · per-dataset `FreshnessPolicy` + staleness columns (ADR-0017) · notifications layer + routes table (ADR-0016) · ApeWisdom poller + popularity history · Nasdaq earnings + corporate-actions (splits/dividends) pollers (ADR-0025) · options 5-min curated REST scan + options EOD full scan (ADR-0020; the curated-scan slice spec must pin the **cycle model**: deterministic scan order, `cycle_id` on rows, per-row event-time rule, overrun policy — BEST_EFFORT skip, tombstone-visible) · `tools/backfill` (equity history seed, adjustment-basis stamped — ADR-0025).
- **Vertical:** the **options-flow detector** — v2's single alert class (ADR-0030) — co-developed with the replay harness, shipping with golden fixtures, the **config-version stamp** on alert rows, and the escalation lifecycle (threshold-tier re-posts, parent-linked — ADR-0026 as amended). Plus the **detector-framework extensibility seams**: detection port, generic alert taxonomy, per-detector config, pluggable rendering.
- **Canary detector:** S003's skeleton threshold detector is **promoted, not deleted** — it stays in production as a **metrics-only canary on `BarClosed`** (consumes the real detection port, increments `canary_decisions_total`, writes no alert rows, touches no user surface). This keeps the streaming→detection seam production-hot and burn-in-observable until a real equity-bar detector ships; if the design session fuses bar context into the options-flow model, the canary demotes to a test fixture.

**Midpoint re-spec rule:** if the appetite is running short, the midpoint re-spec must state an explicit cut-first order for the horizontals; the detector vertical and its substrate (options scans, warm-up, freshness) are never the cut.

**Exit:** full two-band universe streamed/scanned per ADR-0019; all three datasets writing per ADR-0020; warm-up proven by a mid-day restart on the dev box; the options-flow detector has green replay fixtures; extensibility proven in tests (a trivial second detector registers without pipeline changes).

## Phase 3 — Surfaces *(appetite: 4–6 weeks)*

- **`serve` (contract-first):** OpenAPI authored + reviewed → endpoints by group (bars/quotes/movers, popularity, earnings, alerts, portfolio) → `service_clients` auth + per-consumer rate limits (ADR-0012) → the Cowork-shaped consumer test runs green against a live instance.
- **Report-design session** (just-in-time, deferred by ADR-0026): field sets, the top-3 contract ranking basis, serve exposure for Cowork, and the **v2 screener definition** (working recommendation: Schwab movers/`screener_equity` passthrough views — bot command + serve endpoint, no stored state, no user-configurable screeners in v2) — closes before the report slices below.
- **`bot`:** slash + components per ADR-0014 (mobile-first; v1 designs do not anchor) — alert posting with `💵 Trade` button (field-level layout per the alert-presentation spec, written after the Phase-2 detection-model session — ADR-0026) · `/trade buy|sell` manual paper trading (ADR-0027) · `/setup notifications|channels|roles|schwab` · watchlists · report surfaces (no charting — ADR-0026). **Bot data-access rule (ADR-0024 as amended):** all market data via `serve` (no Schwab client, no direct market-data-table reads); direct DB only for user/config state + alert rows; alert embeds render from the alert row alone. Bot code is performance-first (defer early; hot reads via `serve`); **numeric latency budgets are deliberately deferred to this phase's planning** (ADR-0029).
- **`tools/backtest`:** rebuilt on the new datasets as a **`serve` API consumer** (the three-consumer contract — ADR-0011), reusing the replay machinery; validates the options-flow signal via event studies (forward equity returns at 1d/3d/5d/10d — ADR-0020); options strategies forward-only.

**Exit:** parity matrix (below) fully green or explicitly cut; bot dogfoods `serve` where the brief requires it.

## Phase 4 — Terminal burn-in *(fixed window: 3–4 market weeks)*

The complete v2 stack runs unattended against the live market; alerts route to the **private dev channel**; v1 continues serving users untouched. Scheduled rehearsals during the window:

1. One Schwab refresh-token expiry ridden end-to-end: expiry → `SYSTEM_CRITICAL` ntfy push → manual re-auth → stream resumes (gap bounded and *detected*).
2. One deliberate `ingest` restart mid-market-day: warm-up rebuilds state; replay-vs-live state assertion passes; no duplicate or missing alerts.
3. One deliberate `bot` kill during market hours: on reconnect, the `posted_at IS NULL` reconcile posts exactly the missed alerts.
4. One backup-restore rehearsal (ADR-0031): restore the latest VM snapshot to a scratch VM, start the v2 stack against it, run the G2 gap audit; document the post-restore recovery procedure (re-run the 1-min backfill for the lost window; record the options-snapshot hole).

**Finalize freshness budgets** (ADR-0017): provisional `max_age` budgets ship into burn-in from first principles (`cadence × 2`, clamped under value decay). During the window, read the per-dataset `source_last_success_seconds` distribution and set each budget above the observed healthy p99 and below its decay ceiling; write the finalized, dated values into the freshness-budget config table (Postgres — ADR-0017). Budgets are config — this tunes without a redeploy.

Operator involvement otherwise limited to reading dashboards/notifications. Every unscheduled manual intervention is logged — they are gate inputs.

## Phase 5 — Cutover gate + cutover

Cutover proceeds only when **all** criteria hold:

| # | Criterion | Measure |
|---|---|---|
| G1 | Unattended operation | ≥15 consecutive market days full-stack; **0 unscheduled manual interventions in the final 10** |
| G2 | No silent gaps | Two audits, 0 *undetected* gaps in each: (a) **detection log** — no missing stream-built 5-min bar lacking a corresponding `source_status`/staleness record + notification; (b) **research history** — every trading day in the window has complete nightly 1-min backfill coverage, or an alarmed, tombstoned gap (recovery attempted within Schwab's 7-day 1-min window — ADR-0022) |
| G3 | Token lifecycle | Rehearsal #1 passed; downtime within the bound set in the burn-in log |
| G4 | Warm-up | Rehearsal #2 passed (replay state == live state) |
| G5 | Bot reconcile | Rehearsal #3 passed (missed alerts = posted alerts, no dupes) |
| G6 | Timescale jobs | Compression observed having compressed chunks; retention/rollup jobs observed firing (or proven by narrowing a policy window) |
| G7 | Detection liveness | The options-flow detector fired ≥1 real alert during burn-in, or its silence is justified by a replay fixture demonstrating correct no-fire |
| G8 | Serve contract | Cowork-shaped consumer test green against the burn-in instance; rate limiting demonstrated (429 on burst past configured limit) |
| G9 | Backup restore | Rehearsal #4 passed: the restored instance passes the gap audit; data loss bounded by the snapshot cadence (≤24h — ADR-0031) |

**Cutover:** point users at v2 per ADR-0010 clean slate (watchlists recreated; popularity cold-start accepted; burn-in data carries over by default — no preservation value either way). v1 stops but stays **dormant-restartable for 2 weeks** as the rollback hatch; then `legacy/` is deleted and the brief is updated to mark v2 live.

| Manual paper trading (`holdings`/`transactions`/`portfolio_snapshots`) | Rebuilt with `source` discriminator (ADR-0027, Phase 3) |
| Auto-trader | **Cut** — post-v2 service; extraction seam preserved (ADR-0027) |
| Charting | **Cut** (ADR-0026) |
| Backtesting CLI | Rebuilt on new datasets (Phase 3; ADR-0011/0020) |
| EDA | **Deferred** post-v2 (ADR-0011) |
| Admin/config commands | `/setup` umbrella (Phase 3; ADR-0014) |
| Data API / CLI exporter (`api/`) | Superseded by `serve` (ADR-0024) |
