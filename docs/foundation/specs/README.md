# Slice specs

One half-page spec per roadmap slice.
It lands with the code in the implementing pull request and is updated in the same pull request if reality disagrees.
A contested decision gets an ADR instead of a paragraph here.

## Template

- **Goal** - one sentence: what exists afterwards that did not before.
- **Scope** - what is in, and what is explicitly out.
- **Interface** - the tables, functions and Discord surface the slice adds or changes.
- **Acceptance** - one command or observation per criterion, each mapped to the definition of done in the [foundation README](../README.md).
- **Links** - the deciding tickets and the code the slice builds on.

Specs are numbered in roadmap order, for example `01-attention-surge.md`.
